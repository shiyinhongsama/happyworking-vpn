# Implementation Plan: sslvpn-auth

## Overview

按 `SPEC-sslvpn-auth.md` 实现独立 Rust 认证 crate。先打通当前网关的 TLS/HTTP 发现，再实现 V7 和 V3 请求，最后补齐客户端证书、验证码、二次认证和界面验证。

## Architecture Decisions

- HTTP 构造/解析与网络 I/O 分离，协议测试不依赖真实服务器。
- TLS 只通过配置档启用旧算法；自签名证书使用显式指纹信任和 CN 校验。
- 认证结果封装会话 Cookie、能力和注销 URL，敏感字段不进入序列化日志。
- 认证与隧道分离，认证测试通过不代表 TUN 已建立。

## Task List

1. 旧 TLS、HTTP/1.1 边界与 V7 实况发现。
2. V7 密码认证、响应解析与注销。
3. V3 表单认证与兼容解析。
4. 客户端证书、验证码与二次认证。
5. Tauri 认证界面与本机凭据验证。

## Risks and Mitigations

| 风险 | 影响 | 缓解 |
|---|---|---|
| 网关弱 RSA 密钥被现代默认拒绝 | 无法连接 | 显式 legacy 配置 + 固定证书 + CN 校验，实测发现流程 |
| 私有版本字段和双重 URL 编码不一致 | 登录被拒绝 | 使用恢复样例逐字节测试，不打印秘密 |
| 缺少 V3/证书/短信环境 | 无法实况验证 | 本地测试服务与协议样例，保留明确验证状态 |
| UI 误把认证成功当成隧道可用 | 错误状态 | 认证结果单独建模，界面显示“认证成功，隧道未建立” |
